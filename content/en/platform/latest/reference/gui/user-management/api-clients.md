# API Clients

Manage the API clients here: scripts, CI pipelines and other machines that call the management API
without a person signing in. An API client authenticates with its client ID and secret, gets a
short-lived token and sends it with each API call. See
[Access the management API](../../../operations/api/access-the-management-api) for how to use one.

Changes to API clients take effect only after you
[create a revision and deploy it](../../../concepts/configuration-lifecycle). Until then, a new client
can't get a token, and a changed, disabled or deleted client keeps working as before.

## API clients list

### Add API Client {#addApiClientButton}

Click the "Add API Client" button to create a new API client. After saving, the
[secret](#secret) is shown once.

### Client ID {#id-column}

The ID the client authenticates with. See [Client ID](#id) below.

### Description {#description-column}

What the client is used for. See [Description](#description) below.

### Role {#role-column}

The role assigned to the client. See [Role](#role) below.

- **Values:** `Administrator`, `Viewer`

### Enabled {#enabled-column}

Whether the client can get tokens. See [Enabled](#enabled) below.

- **Values:** `Yes`, `No`

### Secret created {#secretRotatedAt-column}

When the client's current secret was created, either together with the client or by
[Regenerate secret](#regenerate-secret).

A warning icon next to the date means that the secret is older than recommended (90 days). Regenerate
it. The warning is only a reminder: the secret keeps working until it is regenerated.

### Edit {#edit-api-client}

Click a table row, or its pencil icon, to open that client in the edit dialog.

### Regenerate secret {#regenerate-secret}

Click the "key" icon to generate a new secret for the client. The new secret is shown once. The old
secret stops working when the change is deployed, so store the new secret where the client reads it
before or right after the deployment. Tokens issued with the old secret stay valid until they expire,
at most 5 minutes.

A client has exactly one secret. To change a secret without any interruption, create a second client
with the same role, switch the script or pipeline to it, then delete the old client.

### Delete {#delete-api-client}

Click the "trashcan" icon to delete the client. It stops working when the change is deployed.

## Create or update an API client

The same dialog is used to create and to edit an API client. When editing, the client ID can't be
changed.

### Client ID {#id}

The ID the client authenticates with when it requests a token. It is also the name the client is
shown with in the logs, for example `ci-pipeline (API client)`.

- **Values:** 3 to 40 characters; lowercase letters, digits and hyphens (`-`) only. Can't be changed
  once the client has been created. The IDs `aero-mgmt` and `aero-core-host` are reserved. API
  clients and [local users](local-users) share one set of names: an ID that is already used by a
  local user is rejected, and so is a new local user with the name of an API client.
- **Required:** yes

### Description {#description}

What the client is used for and who owns it, for example `Nightly deployment, team web`.

- **Values:** free text, at most 255 characters
- **Required:** no

### Role {#role}

Select the role that the client should have. An API client has the same permissions as a user with
that role, with a few exceptions. See
[Roles and permissions](../../../concepts/roles-and-permissions#api-clients).

- **Values:** `Administrator`, `Viewer`
- **Required:** yes

### Enabled {#enabled}

Turn off to block the client without deleting it. After the deployment, a disabled client can't get
new tokens. Tokens it already holds stay valid until they expire, at most 5 minutes.

- **Values:** on, off
- **Default:** on

## API client secret

This dialog opens after a client has been created or its secret regenerated.

### Secret {#secret}

The client's secret, generated by the appliance. Copy it with "Copy secret" and store it in the
secret store of the script or pipeline that uses the client. It is shown only this once; if it is
lost, [regenerate](#regenerate-secret) it. Treat it like a password: anyone who has it can call the
API with the client's role.
